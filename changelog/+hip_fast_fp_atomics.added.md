Add `wp.config.hip_fast_fp_atomics`, also settable per module through the `"hip_fast_fp_atomics"` module option or from the `WARP_HIP_FAST_FP_ATOMICS` environment variable, to lower float32 atomic accumulation to the hardware atomic on HIP devices instead of the compare-and-swap retry loop HIP emits by default (over 100x faster on a contended single address, up to ~1.6x end-to-end on contact-heavy simulations). It covers every float32 accumulation that routes through `wp.atomic_add()`, including `wp.atomic_sub()` and the vector, matrix, quaternion and transform overloads. On by default; set `WARP_HIP_FAST_FP_ATOMICS=0` or `wp.config.hip_fast_fp_atomics = False` for code that accumulates into host-coherent memory Warp did not allocate, such as `CudaManagedAllocator` arrays, where the hardware instruction silently discards updates. No effect on CUDA devices or the CPU.
